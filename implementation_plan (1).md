# Java Lab 1 Studio: Мобільний зв'язок (Варіант 12)

Інтерактивний навчальний веб-інструмент та генератор готового Java-проєкту для початківця, що повністю реалізує вимоги Лабораторної роботи №1 (ООП, Maven, CSV-ініціалізація, JUnit 5 + Mockito, Oracle Java Code Convention та історія Git).

## Підтверджені рішення та налаштування

> [!IMPORTANT]
> Усі ключові технічні параметри підтверджено під час опитування. Після затвердження цього плану буде створено веб-додаток із повним набором готових Java-класів, тестів та інтерактивних симуляторів.

- **Система збірки та тестування**: Maven + JUnit 5 (Jupiter) + Mockito — галузевий стандарт Java, який автоматично підтягується в IntelliJ IDEA без ручного налаштування бібліотек.
- **Формат файлу ініціалізації**: CSV-файл на базі стандартного Java I/O (`BufferedReader` / `java.nio.file`) без зайвих зовнішніх залежностей, зручний для читання, редагування та модульного тестування.
- **Формат веб-додатку**: Комплексна студія — інтерактивна UML-діаграма ООП, живий симулятор консольного меню та CSV-даних, переглядач повного коду проєкту з коментарями для новачка, експорт готового `.zip`-архіву та покроковий гід із командами Git.

## 1. Концепція та цінність додатку

- **Що робить додаток**: Поєднує готовий еталонний Java-проєкт за Варіантом 12 із живим середовищем для його вивчення перед захистом. Користувач може дослідити ієрархію класів, протестувати консольне меню, змінити список тарифів у CSV, переглянути кожен клас і Unit-тест із поясненнями та завантажити одним кліком готовий Maven-архів `.zip`.
- **Цільова аудиторія**: Студент без попереднього досвіду в Java, якому потрібно не просто отримати код, а зрозуміти принципи ООП, структуру пакетів, роботу Mockito та коректно завантажити проєкт на GitHub.
- **Ключова користь**: Усуває поріг входу в екосистему Java — замість розрізнених фрагментів коду користувач отримує цілісний проєкт, що компілюється і проходить тести, та інтерактивний тренажер для підготовки до питань викладача.

## 2. Досвід користувача та візуальний дизайн

### Основні сценарії користувача
1. **Вивчення ієрархії ООП (Вкладка «Архітектура»)**: Користувач бачить інтерактивну UML-схему класів мобільної компанії. Клік на будь-який клас відкриває панель інспектора з полями, методами, поясненням вибору успадкування проти композиції та демонстрацією поліморфізму (`calculateAnnualCost()`).
2. **Робота із симулятором консолі та CSV (Вкладка «Симулятор»)**: Ліворуч працює інтерактивний консольний емулятор мінімального меню Java-додатку (перегляд тарифів, підрахунок загальної кількості клієнтів, сортування за абонплатою, пошук за діапазоном параметрів, перегляд результатів JUnit/Mockito тестів). Праворуч — таблиця тарифів, повзунки діапазонів (абонплата, гігабайти, хвилини) та редактор тарифів, зміни в якому миттєво синхронізуються з файлом `tariffs.csv` для подальшого завантаження.
3. **Перегляд коду проєкту (Вкладка «Код проєкту»)**: Зручний оглядач Java-пакетів (`model`, `criteria`, `repository`, `service`, `ui`, `exception`, тести та `pom.xml`) із підсвіткою синтаксису, номерами рядків, кнопкою копіювання та перемикачем підказок щодо правил Java Code Convention.
4. **Покрокова підготовка до здачі (Вкладка «Гід і Git»)**: Інтерактивний чекліст зі збереженням прогресу: встановлення JDK та IntelliJ IDEA, запуск `mvn test`, пояснення моків Mockito та послідовність із 6 логічних Git-комітів із готовими командами.
5. **Експорт проєкту**: Головна кнопка «Завантажити ZIP» у верхній панелі формує стандартний архів Maven-проєкту (включно з відредагованим `tariffs.csv` та `.gitignore`), готовий до відкриття в IntelliJ IDEA.

### Візуальна ідентичність та тема
- **Естетичний напрямок**: Світла академічно-інженерна студія розробника з високою читабельністю та чітким поділом на навчальний простір і темну зону коду/консолі.
- **Кольорова палітра (правило 60–30–10)**:
  - *60% Основне полотно*: Світло-сірий фон (`#F8FAFC`) для зменшення втоми очей під час вивчення коду.
  - *30% Структурні поверхні*: Білі панелі (`#FFFFFF`) з тонкими розділювачами (`#E2E8F0`) та контрастним текстом (`#0F172A`, `#475569`). Для перегляду коду та консолі використовується глибокий графітовий фон (`#0F172A`).
  - *10% Акцентний бюджет*: Кобальтовий синій (`#0284C7`) для первинної кнопки експорту, активних станів і фокус-кілець; семантичний смарагдовий (`#059669`) та бурштиновий (`#D97706`) завжди в парі з текстовими мітками.
- **Типографіка (правило 2+1 з повною підтримкою кирилиці)**:
  - *Заголовки*: `Plus Jakarta Sans` (600/700) із `text-wrap: balance`.
  - *Основний текст*: `Manrope` (400/500) для чистої читабельності українського тексту.
  - *Код, UML-сигнатури та табличні числа*: `JetBrains Mono` з `tabular-nums`.
- **Компонування**:
  - Однорядна верхня панель із трьох зон: назва студії, 4 однорядкові вкладки навігації та 1 основна кнопка «Завантажити ZIP».
  - Жодних зайвих плашок навколо метаданих (використовуються чисті текстові розділювачі `·`), жодних вкладених карток у картках, чіткий 2-колонковий баланс на десктопі 1440px.

## 3. Ключові архітектурні рішення Java-проєкту (Варіант 12)

### Доцільне використання успадкування та поліморфізму
- **Обраний підхід**: Абстрактний базовий клас `Tariff` (інкапсулює назву, абонплату, кількість клієнтів, інтернет, хвилини, SMS і реалізує `Comparable<Tariff>`) та три змістовні підкласи:
  - `PrepaidTariff` (передплата: цикл 28 днів / 13 періодів на рік, перенесення невикористаних ГБ);
  - `ContractTariff` (контракт: термін договору та відсоток знижки за лояльність);
  - `BusinessTariff` (бізнес: роумінг-хвилини, персональна підтримка, корпоративна знижка).
- **Чому це правильно**: Кожен підклас має унікальні бізнес-атрибути та по-різному перевизначає абстрактний метод `calculateAnnualCost()` (справжній поліморфізм без перевірок `instanceof`). Сервіс `MobileCompanyService` використовує композицію (`TariffRepository`), а не успадкування.
- **Альтернативи**: Плоский клас `Tariff` із полем `type` не продемонстрував би успадкування й поліморфізм; надто глибока ієрархія з 4+ рівнів ускладнила б підтримку без практичної користі.

### Розподіл по пакетах та тестованість із Mockito
- **Обраний підхід**: Чітке розділення відповідальностей за пакетами (`model`, `criteria`, `repository`, `service`, `ui`, `exception`) із впровадженням залежностей через конструктор (Dependency Injection).
- **Чому це правильно**: Впровадження інтерфейсу `TariffRepository` у `MobileCompanyService` дозволяє в Unit-тестах легко замінити читання CSV-файлу моком `@Mock TariffRepository` за допомогою Mockito та перевірити бізнес-логіку ізольовано.

### Збереження стану у веб-студії
- **Обраний підхід**: Клієнтський стан React + `localStorage` для збереження відмічених пунктів чекліста та користувацьких тарифів, а також генерація стандартного `.zip`-архіву безпосередньо у браузері.
- **Чому це правильно**: Миттєвий відгук без потреби у серверній базі даних; користувач може модифікувати тестові дані тарифів і одразу отримати оновлений `tariffs.csv` у своєму Java-архіві.

### Мапінг інтерактивних компонентів та стану
- **UML-інспектор**: Клік по класу оновлює `selectedClassId`, відображає сигнатури, інкапсульовані перевірки, інтерактивний розрахунок поліморфної річної вартості та кнопку «Відкрити в коді», що перемикає вкладку на відповідний Java-файл.
- **Симулятор консолі та CSV**: Вибір пункту меню або введення команди додає структурований вивід у журнал консолі на основі реальних обчислень над поточним масивом тарифів; додавання або видалення тарифу валідує поля (додатна абонплата, невід'ємна кількість клієнтів) та оновлює таблицю, лічильник клієнтів і вміст `tariffs.csv`.
- **Оглядач коду**: Перемикання файлів у дереві пакетів відображає актуальний Java-код (для `tariffs.csv` — динамічно синхронізований із симулятором), підтримує фільтрацію файлів за назвою, режим навчальних пояснень коду та копіювання в буфер обміну.
- **Гід та Git-план**: Відмітка кроків оновлює індикатор прогресу в `localStorage`; кожна Git-команда та команда Maven має робочу кнопку копіювання з візуальним підтвердженням.
